# ТЗ: редизайн CMS thepeak.kz под дизайн-систему основного сайта

## Контекст

Репозиторий: `github.com/fr1en16/thepeak.kz`, локально `/Users/yapil/0/thepeak.kz`.
Next.js 16 (App Router) + TypeScript strict + Tailwind CSS 4 + shadcn/Radix UI. Публичный сайт уже использует зрелую дизайн-систему (шрифт Inter Display, острые углы, коралловый акцент). CMS-панель (`/cms` или аналогичный роут — уточнить у агента при разведке) визуально с этой системой никак не связана: выглядит как дефолтная Tailwind-админка.

**Задача**: не редизайн с нуля, а перенос существующих токенов дизайн-системы сайта на интерфейс CMS. Никакой новой стилистики не изобретать — только то, что уже есть в коде сайта.

## Шаг 0 — разведка (обязательно перед любым кодом)

Прежде чем менять что-либо, агент должен:

1. Найти исходники CMS: `grep -r "CMS" src/app --include=*.tsx -l`, проверить `src/app/cms`, `src/app/admin`, `src/app/(dashboard)` — по факту используемую структуру роутов.
2. Найти текущие токены дизайн-системы:
   - `tailwind.config.*` или `src/app/globals.css` (Tailwind 4 может держать токены в CSS через `@theme`) — искать существующие CSS-переменные (`--color-*`, `--font-*`, `--radius`).
   - Файл шрифта: `next/font/local` для Inter Display — найти вызов (`src/app/layout.tsx` или `src/config`) и имя экспортируемой переменной (`className`/`variable`), чтобы переиспользовать её в CMS-layout, а не подключать шрифт повторно.
   - `components.json` (shadcn) — проверить текущий `baseColor` и `radius`, чтобter понять, что в проекте уже сконфигурировано под 0 радиус или нет.
3. Если часть токенов уже вынесена в переменные — использовать их. Если нет — завести токены по списку ниже в `globals.css` (или там, где уже лежат остальные) и использовать везде через переменные, не хардкодить hex в компонентах.
4. Зафиксировать в PR-описании, что было найдено на этом шаге (какой файл — источник токенов), это часть приёмки.

## Дизайн-токены

Сняты вживую с рендера thepeak.kz (`getComputedStyle`), поэтому это не предположения, а факт:

```css
--peak-bg:        #F2F2F2;  /* было в ТЗ "крем", по правке пользователя — серый; это существующий на сайте светло-серый оттенок (rgb(242,242,242)), не изобретать новый */
--peak-surface:   #FFFFFF;  /* карточки, топбар */
--peak-ink:       #1A1A1A; /* если в токенах сайта уже есть свой ink/foreground — использовать его вместо этого */
--peak-body:      #434343; /* обычный текст, замерено на body сайта */
--peak-muted:     #8E8E93;
--peak-line:      rgba(26,26,26,0.10);   /* hairline-разделители */
--peak-line-strong: rgba(26,26,26,0.18);
--peak-coral:     #FD4B32;  /* акцент сайта, подтверждён: rgb(253,75,50) */
--peak-green:     #2E9E4F;  /* статус "опубликовано" — не с сайта, семантический, подобрать под остальную палитру shadcn если она уже есть (success/positive) */
```

Шрифт: **Inter Display** (900 для заголовков, 600–700 для акцентного текста, 500 для тела), letter-spacing −0.4px на крупных размерах. Файл шрифта уже используется на сайте — переиспользовать `next/font/local` инстанс, не грузить с Google Fonts.

`border-radius: 0` — на всех элементах интерфейса CMS без исключений (кнопки, карточки, инпуты, бейджи). Это принципиальное решение дизайн-системы сайта, не деталь.

## Принцип: это интерфейс управления, а не продающая страница

CMS — рабочий инструмент, а не лендинг. Переносим только цвет/шрифт/острые углы/hairline-стилистику сайта, но **не** переносим приёмы маркетингового хедлайна:

- Никаких крупных hero-заголовков (было 900/56px — заменить на компактный 700/22px) в шапке страниц. Заголовок раздела — просто ориентир, не аргумент продажи.
- Никаких мелких eyebrow-лейблов над заголовком ("ОБЗОР САЙТА · THEPEAK.KZ" и т.п.) — этот приём выдаёт нейросетевой/шаблонный дизайн и не несёт функции в рабочем интерфейсе. Убрать везде, где он появится в макетах или референсах.
- Общий вектор: плотнее, компактнее, меньше воздуха ради воздуха. Шапка страницы — тонкая полоса с заголовком и (опционально) счётчиком/статусом справа, не самостоятельный блок с отступами как на сайте.

Это применимо ко всем экранам CMS, не только к Дашборду — при проектировании Страниц/Кейсов/Аналитики в этапах 3–4 придерживаться того же: заголовок раздела компактный, без eyebrow, без затянутых героических отступов.

## Референс-макет

Приложен файл `thepeak-cms-redesign.html` (статический макет Дашборда) — источник истины по композиции и деталям, **кроме фона**: в макете использован кремовый `#F9F4EB`, в финальной версии заменить на `--peak-bg: #F2F2F2`.

Ключевые элементы макета, которые нужно перенести 1:1:
1. **Топбар**: белый фон, тонкая нижняя граница `--peak-line`, логотип `THEPEAK CMS` (PEAK — акцентным цветом), нав-ссылки uppercase 13px semibold, активный пункт — нижнее подчёркивание 2px `--peak-coral`. Кнопка/статус справа — тёмная плашка (`--peak-ink` фон, `--peak-bg` текст), без радиуса.
2. **Заголовок страницы**: компактная полоса с тонкой нижней границей — `h1` 700/22px (не 900/56px, без eyebrow-лейбла над ним, см. принцип выше).
3. **Stat-bar**: горизонтальная полоса с hairline-разделителями между ячейками (не карточки с фоном/тенью) — цифра 900/32px, подпись под ней серым 13px. Это прямая цитата блока "83% / 10+ лет / 150+ проектов" с главной страницы.
4. **Сетка страниц сайта**: hairline-таблица (border-top + border-left на контейнере, border-right + border-bottom на ячейках) — не card-grid с gap и тенями. Статус (опубликовано/черновик) — текстовый лейбл сверху, не пилюля с фоном.
5. **Crosshair-метки**: маленький coral `+` в верхних углах фреймированных блоков (воронка, топ кейсов) — псевдоэлементы на пересечении hairline-линий. Это сигнатурная деталь сайта (снята с блока формы контактов), обязательна к переносу, но использовать **точечно** — не на каждом блоке подряд, иначе теряет смысл акцента.

## Объём работ (по этапам)

### Этап 1 — токены и layout-обвязка
- Завести/подтвердить CSS-переменные из раздела выше.
- Обновить корневой layout CMS (топбар, фон, типографику) без трогания логики страниц.
- Приёмка: Дашборд визуально соответствует референс-макету с точностью до цвета фона.

### Этап 2 — Дашборд
- Stat-bar с реальными данными (сейчас захардкожено в макете: 4 страницы / 37 кейсов / 3 опубликовано / 7.5% CR) — подключить к реальным данным, которые уже показываются в текущей CMS.
- Сетка страниц сайта (hairline-таблица).
- Панель воронки конверсий и топ кейсов с crosshair-рамкой.

### Этап 3 — Страницы (редактор блоков)
- Не в текущем макете — спроектировать по тем же токенам: hairline-аккордеон для списка блоков вместо плоских карточек, breadcrumbs (Страницы → Главная → Первый экран) в топе.
- Сохранить всю текущую функциональность (drag&drop reorder, загрузка медиа, сохранение) — это чисто визуальный рефакторинг, без изменения поведения.

### Этап 4 — Кейсы, Корзина, Аналитика
- Кейсы/Корзина: применить те же токены к существующей структуре.
- Аналитика: развести текущую "простыню" на табы (Обзор / UTM-кампании / Воронка / География), сохранив все текущие данные и виджеты — просто перегруппировать, не выкидывать метрики.

## Технические требования

- Не ломать существующую функциональность: сохранение страниц, загрузку медиа, drag&drop, аналитические запросы — это визуальный рефакторинг, а не переписывание логики.
- Использовать существующие shadcn-компоненты там, где они уже задействованы (Button, Input, Dialog и т.п.) — перестилить их через токены/варианты, а не заменять на кастомные с нуля, если это не обязательно для получения нужного вида.
- Респонсивность: CMS используется с ноутбука, но не должна ломаться при сужении окна до ~1280px (частый рабочий сценарий с боковыми панелями).
- Доступность: сохранить видимый focus-ring на интерактивных элементах при переходе на `border-radius: 0` — острые углы не должны убирать outline.
- Не добавлять новых внешних шрифтов/CDN — шрифт уже есть в проекте локально.
